# 本轮进展（goal round 17/256）

## 用户报告的 bug：隐藏一个底栏项 → 整条底栏消失

**处置：该规则本轮已撤下（构建并安装完成）**，不再安装，避免继续损坏界面。
`MainHook` 里现在输出：

```
rule=tab_filter status=skipped reason=withdrawn: filtering the shared list blanked
  the whole bottom bar on 9.04.55.32321
```

### 根因分析（诚实：机制已明确，修法未验证）
我的做法是**从数据列表里移除条目**，而这个列表同时被
**底栏本身**和**它的 pager/ViewModel** 消费。子代理早就为顶部频道栏标过同类风险：
「`r1.t(String)` 索引的是**未过滤**的原始列表，只过滤访问器会造成 index 与列表错位」。
底栏看来有同样的耦合，而且失败是**整体性**的（整条栏消失），不是某一个 tab 消失。

次要嫌疑：我返回的是普通 `ArrayList`，而 App 可能期望它自己的列表类型
（Compose/KMM 的状态列表），类型不符会让渲染直接失败。

### 修法方向（下轮，需实机验证后才可重新启用）
1. **不删条目，改隐藏**：保留列表长度，改为 hook「单个 tab 是否可见」的判定
   （与音乐模块「设 setVisibility(GONE) 而不改列表」的思路一致）；
2. 或**只过滤默认组合** `TabBarItemType$a.f()`，不碰 `re0.i.o()/p()/n()`（真正驱动 pager 的那份）；
3. 或**保持列表长度**：把要隐藏的项替换成不可见占位，而不是移除；
4. 无论哪种，重新启用前必须在 9.04.55.32321 上实测「隐藏一个 tab 后底栏仍在、其余 tab 正常」。
