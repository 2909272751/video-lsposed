# 腾讯视频底栏修复与验证 · 2026-09-27

交付：视频精简 0.3.12（versionCode 15，兼容报告 schema 64）。已安装到连接的 Android 16 / LSPosed 2.2.0 手机，腾讯视频 9.04.55.32321。

## 根因与实现

旧规则在生成界面前改动共享标签列表。当前版本 `DataValidator` 会对实际标签数与配置预期数量作等值校验；提前删项会导致 `TabBarViewModel.B0` 直接返回，无法生成完整底栏。旧版反编译目录 `reference-apk/jadx-tabbar` 基于 9.03.95，不能用其中混淆类名代替当前 APK。

新规则只 hook `TabBarViewModel` 校验之后的列表生成入口（当前名称 C0）。按静态签名 `(Ref.ObjectRef, TabBarViewModel) -> Unit` 唯一匹配，并排除编译器生成的 synthetic 转发方法。对已经通过校验的数据创建内存副本，筛选后交给应用生成显示和点击映射，调用完成恢复引用。原缓存、网络响应及数量校验均不修改。背景、图标等其余字段完整保留；首页和个人中心不可被此规则删除。

短剧、会员、好物的语义 pageType 分别为 1、2、21。旧键 show_gallery 对应好片 16，并非好物；新增独立 show_goods 开关，不借用旧键。开关默认显示，当前测试手机已设为仅保留首页与个人中心。

适配不检查特定版本号，也不写死混淆数据类名；通过构造签名、Kotlin 数据字段语义及唯一入口识别。陌生结构、歧义或空导航会原样放行并记录 miss。此策略可抵抗部分混淆变化，但其他版本仍需实测，不能承诺全部兼容。全部显示时不安装该 hook；无界面轮询、无逐帧 Hook。未做耗电基准，因此不宣称量化省电收益。

另修复了开关传输：模块向三个目标应用授予设置 URI 的只读权限，使目标可见并访问 Provider；成功读取会刷新目标侧设置缓存。真实启动报告已记录 `module_provider`，不再被旧缓存盖住。本次未进行手机系统重启；验证的是模块重新打开、腾讯进程强停与重开。
